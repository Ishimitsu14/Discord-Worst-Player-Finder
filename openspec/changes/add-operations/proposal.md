# Proposal

## Why

Модули приложения реализованы, но единой точки запуска, приватного GitHub-репозитория и проверяемой доставки на VPS пока нет. Нужен воспроизводимый запуск одного процесса, который сохраняет SQLite и границу авторазбора при обновлении и не включает платный анализ автоматически.

## What Changes

- Приватный репозиторий `Ishimitsu14/Discord-Worst-Player-Finder`, ветка main, начальный импорт без секретов, БД и локальных снимков.
- Единая точка запуска приложения с явной загрузкой конфигурации/секретов, сборкой публичных модулей и корректной остановкой.
- GitHub Actions: typecheck/тесты на Windows и Linux, Linux-артефакт и последовательный deploy main на Linux + systemd по SSH; pull request не получает deploy-секреты.
- Изолированные пользователь/каталоги/Node runtime сервиса, сохранение данных вне release, проверка revision/health и откат к предыдущему коду при неудачном запуске.
- Неизменная граница automaticSince, prepare-only по умолчанию, live только с явным бюджетом и разрешением experimental. Исторический лимит пилота не переносится.
- Локальная безопасная диагностика и инструкция резервного копирования/восстановления SQLite без повторной отправки неизвестных действий.

## Capabilities

### New Capabilities

- `operations`: явная сборка/остановка сервиса, постоянная рабочая конфигурация, безопасная диагностика, воспроизводимая CI/CD-доставка и сохранность данных при эксплуатации.

### Modified Capabilities

Нет. Контракты соседних модулей сохраняются; operations становится владельцем передаваемых им ресурсов.

## Impact

- Новые `src/operations/`, `test/operations*.ts`, `deploy/`, `.github/workflows/`, корневой README и пример конфигурации. package scripts и пустой env example дополняются без смены Node engines.
- Общий PROJECT_PLAN.md меняется только в строке модуля 9. Принятые модули, схема Storage, prompt, правила анализа и бюджетные проверки не переписываются.
- VPS пользователя: root используется для первичной подготовки; приложение и GitHub deploy получают отдельные учётные записи и ограниченные права. Чужие сервисы не останавливаются, системный Node не заменяется.
- Вне scope: новая калибровка MiMo, платные прогоны, новые Discord-команды, автоматическое разрешение unknown, multi-worker, Docker/Windows service, веб-панель и публичный HTTP API. Реальные токены и host-конфигурация остаются вне Git.
- Подготовка документов сама по себе не означает готовый CI/CD или успешное развёртывание. Реальные результаты фиксируются после проверки; SSH и конфигурация Discord необходимы для запуска бота.
