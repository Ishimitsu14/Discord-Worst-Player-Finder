# Proposal

## Why

Настройки, OpenDota, подготовка фактов, аналитик и SQLite уже реализованы, но пока не образуют общий процесс обработки матча. Нужен модуль, который выбирает подходящие игры и сторону компании, проводит задачу по этапам и учитывает сохранённые исходы до следующей внешней отправки.

## What Changes

- Добавить единый путь ручной постановки по match ID и автоматического обнаружения рейтинговых матчей с минимум двумя разными аккаунтами компании на одной стороне.
- Для авторазбора учитывать только матчи, завершившиеся после явно зафиксированного времени первого включения. Пользователь выбрал этот вариант; перезапуск не устанавливает новую границу и не включает старую историю.
- Выполнять ограниченный повторный просмотр истории с постоянной дедупликацией задач; сообщать о неполном просмотре вместо обещания обнаружить всю историю. Курсор и новый формат БД не добавляются.
- Соединить получение свежего матча, запрос/ожидание разбора, сохранение фактов и точного запроса, анализ и передачу принятого результата будущему модулю публикации.
- Использовать владение и журналы storage, продлевать lease во время ожидания и сохранять поздние исходы без прав устаревшего обработчика.
- По умолчанию готовить данные без внешних POST. Реальный режим требует явной конфигурации лимитов и допуска experimental-пакета; прежний лабораторный бюджет не переносится.
- Ограничить работу одним последовательным обработчиком на БД; перед MiMo проверять известные расходы, неизвестные стоимости и текущую оценку. Автоматических повторов POST в v1 нет.
- Описать минимальный адаптер публикации и локальную интеграционную проверку с поддельными API, включая сбои между этапами.

Изменение не создаёт Discord-команды и embeds, новый HTTP-клиент, критерии/инструкцию модели, финансовую сверку неизвестных расходов, распределённую очередь, bootstrap/VPS или новые платные эксперименты. Рабочие настройки компании остаются прежним JSON. В этом запросе создаются только документы; реализация — по отдельному запросу.

## Capabilities

### New Capabilities

- `match-pipeline`: обнаружение и постановка матчей, последовательная обработка сохранённых задач, контроль внешних действий и наблюдаемый прогресс.

### Modified Capabilities

Нет. Контракты готовых модулей сохраняются; минимальный стык отсутствующего Discord-интерфейса описывается как предложение, без его полной спеки.

## Impact

- Будущий каталог `src/match-pipeline/` с одной публичной точкой экспорта и тесты `test/match-pipeline*.ts`; существующие ESM, TypeScript, node:test и зависимости переиспользуются.
- Зависимости передаются явно: GroupSettings, OpenDotaClient, Storage, закреплённый словарь/PromptPackage, секрет аналитика, часы и необязательный адаптер публикации. Модуль не читает env/файлы при импорте и не открывает свою БД.
- Общий жизненный цикл запуска остаётся operations. Время активации автоматического режима передаётся как постоянный параметр конфигурации; загрузка и сохранность этого параметра — контракт будущего bootstrap, не новая таблица storage.
- Новый процесс использует существующие форматы MatchSnapshot/FactsBundle/PreparedAnalysis/AnalysisAttempt, API владения storage и строковые Discord ID без миграций и изменений соседних исходников.
- Качество MiMo остаётся непроверенным после пилота с length. Проверки конвейера подтверждают маршрутизацию, целостность и защиту от повторов; они не завершают калибровку лаборатории.
