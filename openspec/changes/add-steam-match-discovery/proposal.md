# Proposal

## Why

При десяти аккаунтах частый опрос истории через OpenDota расходует квоту, необходимую для статистики и разбора реплеев. Пользователь выбрал Steam Web API для поиска новых матчей раз в минуту, сохранив OpenDota как источник подробных данных и проверку всех аккаунтов, включая аккаунты с закрытой историей.

## What Changes

- Добавить небольшой клиент Steam `GetMatchHistory`: страницы последних match ID, безопасные ошибки, ограниченные GET-повторы, таймаут, отмена и общий ограничитель запросов.
- В конвейере явно выбирать источник истории. Для Steam использовать минутный интервал; прежние конфигурации с OpenDota сохраняют поведение и параметры по умолчанию.
- Опросить весь список Steam32; `status=15` отметить как недоступную историю, продолжить остальные аккаунты и повторить проверку в следующем цикле. Не удалять аккаунт и не выдавать отказ за пустую успешную историю.
- Разделить обнаружение ID и допуск анализа: Steam не обязан возвращать длительность, исход или полный состав; завершение, режим, постоянную временную границу и двух разных друзей на одной стороне подтверждает свежий OpenDota.
- Сохранять кандидатов и решения в SQLite до появления подходящей задачи. Это позволит пережить запаздывание OpenDota и не запрашивать заново подробности каждого старого матча каждую минуту.
- Обычный запрос по ID переиспользует существующие задачу/отчёт; для ещё ожидающего данных кандидата возвращает понятный статус без платного анализа. Новые slash-команды не нужны.
- Подключить `STEAM_API_KEY` через operations и описать настройку без включения автоматического или платного режима на VPS.
- **BREAKING** для отката формата БД: новая таблица требует следующей версии схемы SQLite. Старый бинарный релиз не обязан открывать обновлённую БД; перед первым обновлением нужен проверенный backup, откат выполняется вместе с совместимой БД.

## Capabilities

### New Capabilities

- `steam-match-history`: ограниченное чтение истории Steam32 через Steam Web API без определения нашей стороны, анализа, SQLite или Discord.

### Modified Capabilities

- `match-pipeline`: выбор источника истории, подтверждение кандидатов через OpenDota, изоляция закрытых аккаунтов и ограниченное ожидание данных.
- `storage`: постоянный журнал кандидатов обнаружения отдельно от задач с уже определённой стороной.
- `operations`: явная конфигурация источника, передача Steam-ключа и безопасная диагностика частичного обнаружения.
- `discord-interface`: ответ существующей команды по ID о кандидате, который ещё ожидает данных OpenDota.

Основной каталог `openspec/specs` пока пуст; существующие одноимённые контракты находятся в изменениях `add-match-pipeline`, `add-storage`, `add-operations` и `add-discord-interface`. Дельты используют эти имена и не переписывают исходные изменения.

## Impact

Планируемые области: новый `src/steam/`, точечные изменения `src/match-pipeline/`, `src/storage/`, `src/operations/`, ответа команды в `src/discord-interface/`, соответствующие тесты и инструкции. Используются существующие TypeScript, `fetch`, SQLite и передаваемые часы; новый процесс, VPS или npm-зависимость не требуются.

В границах этого изменения — обнаружение матчей и необходимые стыки. Не входят переключение аналитика на Gemini, изменение roast/renderer результата, новые workers, обход приватности, STRATZ, GSI, Steam presence, платные API-прогоны, публикации, перенос секретов на VPS и production-доставка. Готовая спека не означает готовую реализацию.
