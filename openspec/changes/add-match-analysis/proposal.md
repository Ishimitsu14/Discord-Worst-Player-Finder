# Proposal

## Why

`match-facts` уже готовит короткий `match-brief-v1`, но приложение ещё не умеет передать его MiMo и получить проверяемый разбор. Нужен самостоятельный аналитик с версионируемой инструкцией, сравнением всех пяти союзников и явным различием между недостатком игровых данных и ошибкой генерации.

## What Changes

- Добавить `match-analysis`: офлайн-подготовку точного запроса из готового пакета фактов, один явный вызов OpenRouter `xiaomi/mimo-v2.6-pro` и локальную проверку результата.
- Отправлять только `match-brief-v1`, инструкцию, схему и допустимые примеры. Полный `facts-v1`, реестр происхождения, сырые снимки и сведения о знакомых аккаунтах остаются вне запроса.
- Ввести самостоятельный формат `match-analysis-v1`: оценки пятерых, предполагаемые позиции, ресурсы, вклад, проблемы, контраргументы, один/два выбранных игрока либо обоснованный отказ, ближайшая альтернатива для одиночного выбора, уверенность и русский roast с 2–3 основаниями на игрока.
- Проверять состав, позиции, допустимость выбора и ссылки во всех фактических полях только на значения, действительно переданные модели. Прохождение структурной проверки не объявлять доказательством смысловой правильности.
- Версионировать инструкцию, схему, профиль и примеры; связывать результат с пакетом фактов и точным запросом через digest. Начальную инструкцию обозначить экспериментальной до реальных проверок лаборатории.
- Различать ошибки входа, конфигурации, маршрута, API, транспорта, отмену, таймаут и невалидный ответ; возвращать доступные usage, стоимость и сведения о генерации также при ошибке после отправки. Не выполнять автоматические повторные генерации.

## Capabilities

### New Capabilities

- `match-analysis`: интерпретация короткого отчёта матча моделью MiMo, обоснованный относительный выбор союзников, проверка ответа и контракт результата для обработки, публикации и исследования качества.

### Modified Capabilities

Нет. Основных спецификаций пока нет. Контракт `match-facts` и сохранённые лабораторные `analysis-v1`/`analysis-v2`, профили и планы сохраняются; новый формат не выдаётся за совместимый с ними.

## Impact

Планируемая реализация: `src/match-analysis/`, пакет `analysis/prompts/v1/`, сфокусированные тесты и документация. Используются существующие TypeScript, Node.js 22.14+, Ajv и `node:test`; отдельный SDK, сервис и новые зависимости не требуются. В `PROJECT_PLAN.md` обновляется только строка модуля 5.

Модуль получает готовый пакет `FactsBundle` через публичный контракт модуля 4. Для будущих модулей 3/6/7 предлагается минимальный контракт попытки и результата; их реализация сюда не входит. Аналитик не получает матчи из OpenDota, не определяет нашу сторону, рейтинговый режим или состав компании, не ведёт очередь, постоянную дедупликацию, SQLite и Discord и не хранит файлы экспериментов.

Реальные платные прогоны, ручные эталоны, расширение корпуса и независимая калибровка остаются работой `evaluation-lab`. Перенос подтверждённых выводов в следующую версию инструкции выполняется явно; готовность кода аналитика не означает подтверждённого качества.
