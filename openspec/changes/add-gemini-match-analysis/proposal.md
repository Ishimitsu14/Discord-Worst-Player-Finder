# Proposal

## Why

Пользователь попросил принять подход Gemini 3.8 Flash с единственным предметным исключением: анализировать нашу команду по Steam32 ID, а не автоматически проигравшую. Нужен новый короткий пакет аналитика: один худший игрок, номинация, 3–4 основания и панчлайн с уместной цитатой из чата; прежние подробные ответы MiMo не дали нужного качества и подачи.

## What Changes

- Добавить новый экспериментальный пакет `gemini-match-v1` для `google/gemini-3.8-flash` и входа `gemini-compact-v1` из [add-gemini-compact-facts](../add-gemini-compact-facts/proposal.md).
- За один потоковый запрос возвращать одного худшего среди всех пяти выбранных союзников после победы и поражения. Чат используется для roast; игровые основания не ссылаются на него.
- Перенести заданные пользователем правила Gemini: защита саппортов, повышенный спрос с коров, нулевой tower_damage, тайминги ключевых предметов, героические показатели и саркастичная русская подача. Зафиксировать эти критерии как выбранную продуктовую эвристику, а не доказанную механику игры.
- Использовать компактную структурированную форму ответа вместо обязательных подробных оценок всех пятерых. Номинация и выбранный слот должны быть однозначны; цитаты проверяются по исходному тексту и автору.
- Профиль: temperature 0.65, low reasoning без экспорта reasoning-текста, ограниченный выход, строгая локальная проверка и отсутствие автоповторов. Время и расходы измеряются, обещание 1.5–2 секунд не становится гарантией.
- Сохранить MiMo/v1, исторические запросы и результаты. Новый формат не маскировать под старый; runtime и публикация требуют явного подключения поддерживающих его потребителей.
- Уточнение пользователя после первого прогона: добавить `gemini-match-v2` с более едким игровым roast и финальными тремя командными факторами поражения; после победы показывать три слабых места. Сохранённый Gemini v1 остаётся воспроизводимым.
- После реального v2 пользователь одобрил шуточную подачу: гиперболы и вольные игровые выводы допустимы и не блокируют приёмку текста. Сохраняются исходные числа, авторство цитат и техническая проверка формата; постоянные оговорки не требуются.
- По новому запросу пользователя добавить сверку сетевого сбоя через management Analytics API и один разрешённый повтор при трёх пустых проверках. Один низкоуровневый анализ остаётся одним POST; workflow ограничен двумя попытками, бюджетом и постоянным журналом.

## Capabilities

### New Capabilities

- `gemini-match-analysis`: один короткий игровой вердикт Gemini с номинацией, основаниями и атрибутированным roast.

### Modified Capabilities

Архивированных capabilities пока нет. Прежний `match-analysis-v1` сохраняется; требования этого изменения действуют только для нового пакета. Продуктовые решения об одной номинации и Gemini согласованы последним запросом пользователя и заменяют прежний целевой подход для будущего запуска.

## Impact

Модуль 5: `src/match-analysis/`, новый пакет в `analysis/prompts/gemini-v1/`, типы/валидация/транспорт, документация и тесты. Модуль 4 — отдельная зависимость. Стыки pipeline/storage/Discord/operations перечислены в design: их старые потребители не считаются совместимыми автоматически. Спека не выполняет платные тесты, не меняет настройки VPS и не включает публикацию.
