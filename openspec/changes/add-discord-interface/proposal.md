# Proposal

## Why

Конвейер уже обнаруживает и обрабатывает матчи, сохраняет результаты и принимает Publisher, но у друзей пока нет Discord-команд и итоговых сообщений. Нужен интерфейс, который ставит задачи и показывает сохранённый разбор, не дублируя анализ, очередь и защиту внешних отправок.

## What Changes

- Добавить guild-команды `/worst match_id [side]`, `/worst-status job_id` и отдельную `/worst-reanalyze match_id side` с русскими описаниями и приватными служебными ответами.
- Применить выбранную пользователем политику: обычная постановка и чтение доступны участникам заданного канала; повторный анализ требует Discord Administrator. DM, другой сервер и другой канал не дают доступа к задачам.
- Передать ручные запросы существующему MatchPipeline; для повторного анализа использовать постоянный ключ из interaction ID. Статус и сохранённый результат читать без нового OpenDota/MiMo запроса.
- Сформировать один русский embed по принятому selected/insufficient-evidence: ник и герой, один/два худших, roast, 2–3 основания на каждого, исход стороны, ограничения и ссылка OpenDota. Ники брать из сохранённого snapshot, героев — из facts, не добавляя привязок аккаунтов к людям.
- Реализовать существующий Publisher-порт через Discord REST с точным сохранённым JSON, запретом mentions и скрытых повторов create-message. Известный message ID остаётся дедупликацией storage; неопределённый исход передаётся конвейеру без автоматического repost.
- Предоставить явную регистрацию только собственных guild-команд и подключение/отключение interaction listener. Проверить реальные SDK-пути с поддельным транспортом и временной SQLite без подключения бота к Discord.

Граница — модуль 6 `discord-interface`. Он не обнаруживает матчи, не выбирает худшего, не запускает worker, не меняет инструкции MiMo/расходные лимиты/схему storage и не разрешает unknown. Login/token loading, постоянная конфигурация, автоматический запуск, VPS и новые реальные платные эксперименты остаются вне изменения. В этом этапе создаются только документы; реализация — отдельным запросом.

## Capabilities

### New Capabilities

- `discord-interface`: ограниченный заданным сервером/каналом доступ к командам обработки и чтения, русское представление сохранённого анализа и публикация через журналируемый порт.

### Modified Capabilities

Нет. Публичные контракты group-settings, match-pipeline, match-analysis, match-facts и storage сохраняются.

## Impact

- Будущие `src/discord-interface/` с одной точкой экспорта, README/VERIFICATION и `test/discord-interface*.ts`.
- При реализации — закреплённая зависимость discord.js ветки 14 с проверкой Node >=22.14.0 и lock-файлом. На этапе планирования пакет не устанавливается и engines не меняются.
- Используются готовые GroupSettings, MatchPipeline, PublicationContext/PublicationInput/PublicationError и публичное чтение артефактов Storage; новых таблиц и новых полей рабочего JSON нет.
- Реальные права бота и приём сообщений на сервере остаются отдельной runtime-проверкой после настройки приложения. Текущая калибровка MiMo этим интерфейсом не завершается.
