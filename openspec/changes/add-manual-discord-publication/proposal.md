# Proposal

## Why

Пользователь хочет, чтобы бот заранее разбирал только новые совместные матчи, но не публиковал результат без команды в Discord. Сейчас автоматическая обработка после valid сразу вызывает Publisher, поэтому перед production-запуском нужен отдельный режим ожидания публикации.

## What Changes

- Добавить opt-in `publicationMode=on-command`; прежний `automatic` остаётся совместимым default.
- Автоматически найденный матч проходит обычные факты/Gemini/учёт стоимости и сохраняется без Discord POST. `/worst` для готового результата разрешает одну публикацию; `/worst-status` остаётся чтением.
- Повтор команды, рестарт и неизвестный исход не создают второй платный анализ или публичную копию. Ручной запуск нового матча по `/worst` сам является явным запросом разбора и публикации.
- Сохранить существующую границу `automaticSince`: только матчи, завершившиеся после первого включения, без авторазбора старой истории. Перезапуск не переносит границу.
- Обновить понятные состояния «разбор готов, ждёт команды» и «публикация в очереди»; production-настройки и секреты держать вне Git.

## Capabilities

### New Capabilities

- `on-demand-publication`: постоянное ожидание явной публикации готового автоматического разбора, совместимое с текущими очередью и журналом внешних попыток.

### Modified Capabilities

Нет перенесённых main specs; используются контракты завершённых changes `add-match-pipeline`, `add-storage`, `add-discord-interface`, `add-steam-match-discovery` и `add-operations`.

## Impact

Основной scope — pipeline; необходимы узкий метод Storage, Discord-тексты и operations-проверка новой настройки. Схема SQLite и модельный контракт не меняются. Используются существующие waiting/reason, сохранённый valid и журнал publication. Без новых библиотек, worker, HTTP API, изменения списка друзей, сброса данных/расходов или автоматической публикации накопленных результатов.
