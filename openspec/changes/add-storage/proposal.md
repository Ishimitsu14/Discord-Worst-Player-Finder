# Proposal

## Why

Готовые клиенты OpenDota и MiMo ещё не имеют постоянного журнала задач и внешних запросов. До сборки конвейера нужно сохранять результаты и различать безопасное продолжение после сбоя от неопределённой отправки, которая могла уже создать задание, списать деньги или опубликовать сообщение.

## What Changes

- Добавить локальное SQLite-хранилище обнаруженных матчей, задач по стороне и ревизиям, снимков входных данных и результатов анализа.
- Зафиксировать дедупликацию первого ручного/автоматического запуска по match ID и стороне; повторный анализ создавать отдельным явным намерением с новой ревизией, сохраняя историю.
- Сохранять неизменяемый контекст обработки, точные запросы/digests, StartedAttempt и AnalysisAttempt существующего аналитика, расходы и неизвестность стоимости.
- Предоставить атомарное получение задачи, ограниченное владение с fencing token и условные переходы состояния; восстановление не должно автоматически повторять неопределённые внешние действия.
- Ввести отдельные журналы запроса разбора OpenDota и публикации Discord; известный job ID и message ID сохранять для продолжения и показа результата.
- Различать одноразовую фиксацию разрешённой отправки и идемпотентное сохранение её результата. При ошибке фиксации внешнее действие не допускается.
- Описать миграции, безопасные ошибки, локальное размещение БД и контракт проверки на настоящих временных SQLite-файлах.

В изменение не входят поиск совместных игр, выбор стороны, критерии оценки, сетевые обращения, Discord-команды/embeds, автоматические повторы API, правила пользовательского бюджета, резервное копирование по расписанию, VPS и реализация остальных модулей. Рабочие настройки компании остаются в JSON; SQLite хранит только неизменяемые снимки контекста конкретных задач, а не второй редактируемый источник настроек.

## Capabilities

### New Capabilities

- `storage`: постоянное хранение задач, артефактов, попыток внешних действий и результатов с атомарными изменениями и безопасным восстановлением.

### Modified Capabilities

Нет. Реализованные модули не меняются; стыки отсутствующих match-pipeline и discord-interface описываются как минимальные предложения для последующего согласования.

## Impact

- Планируемый каталог `src/storage/`, одна публичная точка экспорта; существующие TypeScript, Node.js 22.14+ и node:test переиспользуются.
- Предлагается встроенный node:sqlite без ORM и новых npm-зависимостей; локальная проверка подтвердила DatabaseSync в Node.js 22.14.0. Экспериментальный статус этого API и выбор rollback journal описаны в design.md; это предложение для реализации после рассмотрения спеки.
- Будущий pipeline передаёт проверенные данные и управляет порядком/бюджетом/повторами, аналитик использует beforeSend, Discord сохраняет результат публикации. Хранилище не запускает сеть или фоновые обработчики.
- Путь к БД задаёт вызывающий код, рекомендованное локальное размещение — `.local/app.sqlite`. Секреты, файлы БД, журналы SQLite и реальные артефакты остаются вне Git.
- Подготовка proposal/design/spec/tasks отделена от реализации. По последующему запросу реализован модуль `src/storage/`; выполнение задач и результаты проверки отражены в tasks.md и `src/storage/VERIFICATION.md`. Интеграция приложения остаётся отдельным этапом.
