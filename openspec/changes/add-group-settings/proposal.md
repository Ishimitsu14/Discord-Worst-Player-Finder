# Proposal

## Why

Остальным модулям нужен единый проверенный список аккаунтов компании и один адрес публикации в Discord. Отдельный небольшой модуль настроек позволит обнаруживать ошибки локальной конфигурации до запуска обработки матчей, не связывая аккаунты с людьми и не вводя базу настроек раньше необходимости.

## What Changes

- Добавить загрузку локального JSON-файла с тремя обязательными полями: `steamAccountIds`, `guildId`, `channelId`.
- Проверять непустой список уникальных числовых Steam32 account ID в диапазоне, принятом контрактом клиента OpenDota; не преобразовывать Steam64, ссылки или ники.
- Проверять строковый формат Discord ID без потери точности; отделить проверку формата от сетевой проверки сервера, канала и прав бота.
- Возвращать остальным модулям неизменяемый снимок настроек; изменения файла применять при следующем запуске приложения.
- Выдавать понятные ошибки чтения, JSON и содержимого без частичного результата, скрытых значений по умолчанию и вывода содержимого файла.
- Подготовить при реализации пример с вымышленными ID и инструкцию локальной настройки; реальный файл держать вне Git, секреты передавать отдельно.

В границы изменения не входят Discord-команды редактирования, горячая перезагрузка, несколько компаний/серверов/каналов, привязки к людям, SQLite, проверка аккаунтов через API, выбор матчей или стороны, порог совместной игры, параметры OpenDota/MiMo, секреты и развёртывание. Проверка доступности канала и прав публикации принадлежит `discord-interface`; выбор источника пути и порядок запуска приложения — `operations`.

## Capabilities

### New Capabilities

- `group-settings`: загрузка, проверка и предоставление единой локальной конфигурации аккаунтов компании и адреса публикации.

### Modified Capabilities

Нет. Контракты существующих изменений не меняются; полные спеки соседних модулей не создаются.

## Impact

- Планируется самостоятельный TypeScript модуль `src/group-settings/` с одной публичной точкой экспорта. Прикладного кода, общей сборки и установленных зависимостей в проекте сейчас нет.
- `match-pipeline` получит список аккаунтов, `discord-interface` — ID сервера и канала. SQLite не становится вторым источником настроек.
- Используются встроенные средства Node.js без сетевых вызовов и без новых runtime-зависимостей. Путь к файлу явно передаётся вызывающим кодом.
- Пример, README и исключение локального каталога будут добавлены при реализации. На этапе этой спеки создаются только документы; реальная конфигурация и секреты не запрашиваются и не сохраняются.
