# Spec Delta

## Purpose

Предоставлять модулям бота единый проверенный список Steam32 аккаунтов компании и адрес публикации в Discord. Обнаруживать ошибки локальных настроек до их использования без сетевых запросов и привязок аккаунтов к людям.

## ADDED Requirements

### Requirement: Явный локальный источник настроек

Модуль SHALL загружать настройки только из локального JSON-файла по явно переданному непустому пути. Файл SHALL содержать объект с обязательными полями `steamAccountIds`, `guildId`, `channelId`. Неизвестные поля SHALL отклоняться; модуль SHALL NOT подставлять значения из окружения, примера, SQLite или другой конфигурации.

#### Scenario: Корректный файл
- **WHEN** по переданному пути находится корректный файл со всеми тремя полями
- **THEN** модуль возвращает настройки только из этого файла

#### Scenario: Путь не задан
- **WHEN** путь пустой или содержит только пробельные символы
- **THEN** модуль возвращает ошибку входных настроек без поиска файла по умолчанию

#### Scenario: Нет обязательного поля
- **WHEN** отсутствует любое обязательное поле или вместо объекта переданы `null`, массив либо примитив
- **THEN** модуль отклоняет конфигурацию целиком без частичного результата

#### Scenario: Лишнее поле или несколько адресов публикации
- **WHEN** объект содержит неизвестное поле, например `guilds`, `channelIds`, `owners`, `discordToken` или параметр порога совместной игры
- **THEN** модуль возвращает ошибку содержимого без сохранения или использования неизвестного значения

#### Scenario: Некорректный источник при наличии другого
- **WHEN** переданный файл отсутствует или невалиден, а рядом есть пример, старый файл или настроены переменные окружения
- **THEN** модуль возвращает ошибку переданного источника без перехода на другой источник

### Requirement: Уникальные аккаунты компании в формате Steam32

`steamAccountIds` SHALL быть непустым массивом уникальных чисел, каждое из которых является целым от 1 до 4294967294 включительно. Модуль SHALL сохранять порядок и значения аккаунтов без привязок к людям, владельцам или Discord-пользователям и SHALL NOT преобразовывать строки, Steam64, ссылки или имена в Steam32.

#### Scenario: Несколько аккаунтов
- **WHEN** передан массив разных допустимых Steam32 account ID
- **THEN** результат содержит все ID в исходном порядке без объединения по предполагаемому владельцу

#### Scenario: Один аккаунт
- **WHEN** передан массив с одним допустимым account ID
- **THEN** настройки принимаются без изменения списка и без обещания, что выполнено условие автоматического разбора

#### Scenario: Пустой список
- **WHEN** массив пуст, поле равно `null` или не является массивом
- **THEN** модуль отклоняет настройки

#### Scenario: Границы диапазона
- **WHEN** список содержит разные значения 1 и 4294967294
- **THEN** оба значения принимаются

#### Scenario: Неверное значение аккаунта
- **WHEN** элемент списка равен 0, 4294967295, отрицательному или дробному числу, выходит за допустимый диапазон либо имеет другой тип, включая строку с цифрами
- **THEN** модуль возвращает ошибку с позицией элемента без исправления или пропуска значения

#### Scenario: Steam64 или ссылка вместо Steam32
- **WHEN** элемент содержит Steam64, Steam-профиль, Steam2/Steam3 ID или ник
- **THEN** модуль отклоняет конфигурацию без конвертации и сетевого поиска аккаунта

#### Scenario: Дубликат
- **WHEN** один допустимый account ID встречается в массиве повторно
- **THEN** модуль отклоняет конфигурацию с указанием позиции повторения без молчаливого удаления дубликата

### Requirement: Один адрес публикации без потери точности

`guildId` и `channelId` SHALL быть строками положительных десятичных целых без пробелов, знака и ведущих нулей, со значением не более 18446744073709551615. Модуль SHALL сохранять их точный строковый вид, SHALL NOT принимать числовой JSON ID и SHALL NOT ограничивать ID фиксированным количеством из 18 или 19 цифр.

#### Scenario: Строковые ID
- **WHEN** оба поля содержат допустимые строковые ID, в том числе превышающие безопасную точность числового типа
- **THEN** модуль возвращает исходные строки без округления

#### Scenario: Числовой ID
- **WHEN** `guildId` или `channelId` задан JSON-числом, даже если оно целое и небольшое
- **THEN** модуль отклоняет поле без преобразования в строку

#### Scenario: Неверный формат или диапазон
- **WHEN** любое поле равно пустой строке, `null`, `"0"`, содержит пробелы, ведущий ноль, знак, дробь, экспоненту, упоминание, URL или значение больше верхней границы
- **THEN** модуль возвращает ошибку соответствующего поля

#### Scenario: Формат не подтверждает доступность
- **WHEN** строковые ID проходят локальную проверку
- **THEN** модуль принимает их без утверждения, что сервер и канал существуют, канал принадлежит серверу или бот имеет право публиковать

### Requirement: Переносимое чтение и явные ошибки

Модуль SHALL читать UTF-8 JSON с необязательным одним начальным BOM на Windows и Linux. Он SHALL различать ошибку чтения, синтаксиса JSON и содержимого настроек. Любая ошибка SHALL завершать загрузку без результата; диагностическое сообщение SHALL содержать понятную причину и путь поля, когда ошибка относится к известному полю.

#### Scenario: Файл с BOM и разными окончаниями строк
- **WHEN** корректный UTF-8 JSON записан с начальным BOM или без него, с CRLF или LF
- **THEN** содержимое настроек принимается одинаково

#### Scenario: Файл недоступен
- **WHEN** файл отсутствует, недоступен для чтения или переданный путь указывает на каталог
- **THEN** модуль сообщает ошибку чтения без создания файла и без результата

#### Scenario: Невалидный JSON
- **WHEN** файл пуст, оборван, содержит комментарии, лишнюю запятую или другую синтаксическую ошибку
- **THEN** модуль сообщает ошибку JSON отдельно от ошибки чтения и проверки полей

#### Scenario: Невалидное содержимое
- **WHEN** JSON корректен, но тип или значение известного поля нарушает контракт
- **THEN** модуль сообщает ошибку содержимого с путём поля или элемента, например `steamAccountIds[1]`

### Requirement: Единый неизменяемый снимок

После успешной загрузки модуль SHALL предоставлять снимок, значения которого нельзя изменить через возвращённый объект или массив аккаунтов. Модуль SHALL NOT следить за файлом или автоматически обновлять ранее выданный снимок. Настройки приложения SHALL применяться при запуске; для изменения рабочей конфигурации требуется перезапуск.

#### Scenario: Использование несколькими модулями
- **WHEN** вызывающий код передаёт полученный снимок обработке матчей и Discord-интерфейсу
- **THEN** потребители получают одни и те же проверенные значения и не могут изменить снимок друг друга

#### Scenario: Файл изменён после загрузки
- **WHEN** локальный файл отредактирован или удалён после успешной загрузки
- **THEN** существующий снимок сохраняет прежние значения без фонового чтения или частичного обновления

#### Scenario: Следующий запуск
- **WHEN** при следующем запуске вызывающий код повторно загружает настройки из изменённого файла
- **THEN** возвращается новый снимок либо ошибка новой конфигурации без скрытого использования прежней

### Requirement: Отсутствие побочных обращений

Загрузка настроек SHALL выполнять только локальное чтение и проверку. Модуль SHALL NOT обращаться к OpenDota, Steam, Discord, OpenRouter или SQLite, создавать задания, выбирать матчи или проверять наличие двух аккаунтов на одной стороне. Успешная загрузка SHALL означать только корректность локальной конфигурации.

#### Scenario: Работа без сети и секретов
- **WHEN** сеть недоступна, секреты не заданы и база приложения не создана, но локальный файл корректен
- **THEN** загрузка успешно возвращает настройки без внешних обращений и записи данных

#### Scenario: Неизвестный API аккаунт
- **WHEN** синтаксически корректный account ID отсутствует в данных OpenDota или его история недоступна
- **THEN** модуль настроек не запрашивает историю и не исключает аккаунт из снимка

### Requirement: Локальные данные и безопасная диагностика

Пример конфигурации SHALL содержать только явно вымышленные ID; документация SHALL указывать локальный путь вне Git и отдельную передачу секретов. Ошибки и собственные логи модуля SHALL NOT содержать текст файла, значения полей или исходные исключения парсера, способные раскрыть случайно записанный секрет.

#### Scenario: Пример для настройки
- **WHEN** пользователь открывает пример и инструкцию
- **THEN** он видит назначение трёх полей, способ создания локального файла, требование перезапуска и указание, что реальные ID нужно заменить самостоятельно, а токены в JSON не помещать

#### Scenario: Секрет ошибочно помещён в JSON
- **WHEN** файл содержит неизвестное поле с токеном или повреждён так, что ошибка JSON могла бы вывести фрагмент содержимого
- **THEN** диагностика сообщает категорию и безопасную причину без значения токена, текста JSON и исходного сообщения парсера
