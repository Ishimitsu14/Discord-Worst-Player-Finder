# Проверка match-analysis — 17 октября 2026

Реализован самостоятельный аналитик: офлайн-подготовка запроса из FactsBundle, экспериментальный пакет MiMo, `match-analysis-v1`, проверка всех Claim, единичный транспорт OpenRouter и контракт попытки. Реальных генераций и калибровки качества не было.

## Автоматические проверки

- Windows, Node.js 22.14.0; существующие TypeScript/Ajv/`node:test`, без новых зависимостей.
- `npm.cmd run typecheck` и `npm.cmd run build` проходят.
- `npm.cmd test`: 122/122 теста проходят, включая 24 новых проверки аналитика и все 98 прежних. Финальный локальный протокол: `.local/match-analysis/tests-final-cbffd590-e033-4ab0-9210-d7ff182c0735.tap`.
- `openspec.cmd validate add-match-analysis --type change --strict --no-interactive` проходит.
- Импорт без ключа и сети, целостность частей/манифеста, поддерживаемые версии/закрытый контекст, обе стороны/исходы, анонимность, неизвестные/ручные позиции и отсутствие мутации проверены.
- Проверены bytes пакета и изменение digest запроса при правке каждого из четырёх файлов; experimental/пустые примеры, обязательный отчёт candidate, недопустимые профиль/схема и утечка целевого match ID/holdout через пример.
- Проверены точные UTF-8 границы Brief/запроса, Unicode, переполнение с примерами, отсутствие скрытого сокращения и сохранение копии пакета. Документированный `analysis/examples/prepare.mjs` выполнен через отдельный Node-процесс без ключа.
- Валидатор проверен на одиночном выборе, паре, третьем/вражеском/повторном кандидате, отказе, пятёрке/позициях/source, обязательной альтернативе, пропусках и размерах. Проверяются ссылки каждого раздела всех пятерых и стабильные адреса Claim, включая пару и отказ. Допустимая групповая ссылка отличается от исключительно локального ID её члена.
- Подменённый OpenRouter проверяет GET metadata → beforeSend → один POST с точным requestDigest. Покрыты все достижимые endpoint, неподтверждённый fallback, тарифы/кеш и оценочный предел; отсутствие ключа, испорченный запрос/пакет, cooldown, отказ/зависание/поздний callback, отмена до/после POST и общий таймаут metadata/callback/ответа/JSON.
- Проверены HTTP 400/401/402/403/408/429/5xx, ошибки верхнего уровня/choice при HTTP 200, чужая/неизвестная модель, tools/refusal, пустой/усечённый/обёрнутый в Markdown/невалидный JSON и неизвестные ссылки. Исправляющих POST нет. Retry-After проверен для metadata и генерации, секунд/HTTP date/невалидного значения.
- UTC/elapsedMs, идентичность, разные attemptId, сохранённый started при потере итоговой записи, известный/нулевой/частичный/неизвестный usage, стоимость невалидного ответа и billingState проверены. Ключ не экспортируется через content/ID/model/provider/finishReason/сырую ошибку; headers/reasoning/произвольные metadata исключены.
- Сеть в прогонах подменена. Синтетические ответы находятся только в тестах, реальные снимки не добавлены в исходники. Старые лабораторные пакеты и runner не изменены.

Первый полный прогон внутри песочницы получил запрет Windows hard links (`EPERM`) в существующих файловых тестах лаборатории. Полный прогон с локальными разрешениями прошёл; после добавления обработки Retry-After на GET он повторён успешно. Небезопасный fallback записи не добавлялся.

## Оставшиеся живые проверки

- Пакет остаётся `experimental`; содержательная правильность выбора/аргументов, русский язык и пригодность roast не подтверждаются структурным valid.
- Доступность маршрута, принятие точной строгой схемы, реальные токены/расходы/время и влияние reasoning upstream-default требуют явных генераций с бюджетом и пользовательского ревью.
- Подключение нового контракта к prepare/run/report лаборатории и независимый holdout — отдельный следующий этап; четыре обсуждавшихся матча не являются holdout.
- Фактический runtime Linux не проверен. Публичные API, NodeNext и пути загрузчика используют стандартные средства Node.js; это не заменяет запуск на Linux.
- Постоянный приёмник started, сохранение итогов, дедупликация, общий бюджет и восстановление после сбоя процесса остаются контрактом будущих pipeline/storage. В тестах приёмник работает в памяти.
