# Аналитик MiMo

Самостоятельный модуль поверх публичного `FactsBundle`. Контракт: [OpenSpec](../../openspec/changes/add-match-analysis/specs/match-analysis/spec.md), решения: [design.md](../../openspec/changes/add-match-analysis/design.md).

Core не читает окружение/файлы и не вызывает сеть при импорте. Зависимости — существующие TypeScript, Node.js 22.14+ и Ajv. Ключ, fetch, отмену и приёмник `started` передаёт вызывающая сторона; очередь, постоянное хранение, уникальность attemptId, повторный запуск и общий бюджет остаются у неё.

Вход получают через `prepareMatchFacts` либо проверяют `verifyFactsBundle` с исходным снимком/options. Аналитик проверяет форму и целостность; заново вычисленный злоумышленником hash не доказывает подлинность данных OpenDota. Модели предназначен только `context`, полные `facts` и `evidence` остаются локально.

Первый пакет инструкции экспериментальный. Изолированные тесты проверяют контракт, а реальное качество выбора, интерпретации и roast требует пользовательского ревью лаборатории.

## Пакет и офлайн-запрос

`loadPromptPackage('analysis/prompts/v1')` читает четыре UTF-8 файла явно. `createPromptPackage(files, calibrationEvidence?)` делает то же из строк без файловой системы; core не обращается к диску. Digest учитывает точные bytes каждого файла и его имя; пробел или новая строка меняют digest. Принимаются только две закреплённые схемы `match-analysis-v1`: исходная и переносимая из пакета v2. Произвольное ослабление структуры или пределов не принимается. Функции возвращают собственные копии входного пакета.

Начальные параметры: temperature 0.2, max_tokens 8192, reasoning upstream-default. Строгая схема и allowlist deepinfra/gmicloud/xiaomi сохраняются в точном теле. Пакет experimental имеет calibrationReport null. Для candidate требуется ссылка/digest существующего отчёта и его bytes со stage candidate, рекомендацией candidate и ревизией ручного ревью; загрузчик читает путь относительно каталога пакета. Эти признаки проверяют целостность заявления, а смысл и применимость отчёта подтверждает владелец пакета.

Отдельный экспериментальный `loadPromptPackage('analysis/prompts/v2')` сохраняет исходную инструкцию, но убирает pattern у свободного текста: проверенный маршрут Xiaomi с исходным `\\S` выдавал по одной букве. Пакет v2 явно отключает рассуждения через `reasoning: {enabled:false}`, задаёт max_tokens 32768 и только Xiaomi без fallback. Preflight требует поддержки `reasoning`; фактическое отключение проверяется по usage. Исходные v1 bytes и подготовленные запросы сохраняются. Выбор v2 выполняет caller явно; runtime по умолчанию не переключается.

`examples.json` начинается пустым. Каждый будущий пример содержит context, analysis и provenance с matchId/side, snapshotDigest/contextDigest, split development, labelRevision/reviewRevision. Пример проходит проверку формы Brief/ответа, digest, происхождения и запрета целевого match ID, включая другую сторону. Подлинность ручного вердикта не доказывается строкой ревизии. Модель получает только context и analysis примера; происхождение и эталон целевого матча не отправляются.

```ts
import { loadPromptPackage, prepareAnalysis } from './src/match-analysis/index.js';

const prompt = await loadPromptPackage('analysis/prompts/v1');
const prepared = prepareAnalysis(bundle, prompt);
// prepared.body — точный JSON без ключа, prepared.requestDigest — SHA-256 этих bytes.
```

Исполнимый пример читает четыре файла пакета, сохранённые командой `lab facts`, и выводит только идентичность/размеры. Из корня проекта в PowerShell:

```powershell
npm.cmd run build
node analysis/examples/prepare.mjs .local/evaluation/facts/<UUID>
```

В Linux используется `npm run build`; Node-команда та же. Пример не требует ключа, не обращается к сети, не записывает файлы и не загружает отсутствующий снимок. Каталог подставляется существующий; ввод raw OpenDota вместо FactsBundle не поддерживается.

Предел Brief — 65536 bytes точного minified UTF-8, запроса — не более 262144 bytes (профиль может уменьшить). Переполнение даёт ошибку без удаления игроков, драк и примеров. `ceil(requestBytes / 2)` — маркированная эвристика utf8-bytes-div-2-v1; это не токенизатор, гарантия контекстного окна или измерение расходов/скорости.

## Ответ и ручное ревью

`validateMatchAnalysis(json, bundle)` проверяет формат match-analysis-v1, пять уникальных союзников и их position/source, один/два выбора, статус, альтернативу и ссылки. У выбранного ровно 2–3 reasons и roast. У Claim/roast предел 600 Unicode символов; contributions/concerns до трёх, evidenceIds от 1 до 12 уникальных ID; limitations до восьми строк по 300 символов. Любой пропуск ресурса/контраргумента/вклада/проблем объясняется limitations игрока.

Во всех утверждениях, roast и строках limitations после trim требуется минимум два Unicode code points. Отдельная буква или один emoji отклоняются как `invalid-output`; для отправленного ответа usage сохраняется, исправляющей генерации нет. Этот фильтр выявляет вырожденную форму и не подтверждает смысл или русский язык. Старые записи не переписываются, но повторная локальная проверка и оформление публикации используют актуальный фильтр.

`insufficient-evidence` — пригодный содержательный ответ: пять оценок, пустой выбор, null comparison/alternative, low confidence и ограничения. Ошибка API или провайдера этим статусом не маскируется.

Ссылки проверяются во всех Claim: оценки пятерых, reasons, comparison и альтернатива. Допустим ID переданной именованной группы; ID её члена, оставшийся лишь в локальном реестре, не принимается. Структурная проверка не доказывает смысл: правильность метрики/слота, причинности, русского языка, выбора и шутки проверяется вручную.

`analysisClaims(analysis)` возвращает `{address:{section,playerSlot,index},fact}` по стабильным адресам. Ревью отдельно фиксирует: согласие с выбором; верность каждого Claim и ограничения роли/причинности; пригодность roast и отсутствие в нём новых обвинений. Форматы Review v2 лаборатории не меняются и не становятся совместимыми с новым списком автоматически.

## Сетевое выполнение

`analyzeMatch(prepared, bundle, options, dependencies)` возвращает AnalysisAttempt. Options: уникальный `attemptId` из 1–128 букв/цифр/`_`/`-`, явный положительный `maxEstimatedCostUsd`, необязательные timeoutMs (по умолчанию 180000, от 1 до 2147483647 мс) и notBefore (ISO UTC). Dependencies: apiKey, обязательный асинхронный beforeSend, необязательные fetcher и signal. Ключ получает точка сборки из `OPENROUTER_API_KEY`; модуль не читает его самостоятельно.

Перед сетевым выполнением повторно проверяются запрос/пакет/вход, затем один GET актуальных endpoint и оценка цены по максимальным применимым тарифам всех разрешённых маршрутов. Если хотя бы один достижимый маршрут не подтверждает схему/параметры/контекст/цену, генерации нет. Тело не меняется под доступный маршрут; нужен явно подготовленный другой профиль. System-сообщение включает ID и digest пакета, поэтому любая правка его четырёх файлов меняет digest запроса.

После preflight beforeSend получает собственную копию StartedAttempt с плоской идентичностью и оценкой стоимости. Только после успешного завершения callback выполняется один POST. Вызывающая сторона обязана сохранить started постоянно и затем сохранить возвращённый итог. Пример подключения к будущему хранилищу:

```ts
const result = await analyzeMatch(prepared, bundle, {
  attemptId, maxEstimatedCostUsd,
}, {
  apiKey, signal,
  beforeSend: started => storage.saveStarted(started),
});
await storage.saveAttempt(result);
```

storage здесь — интерфейс caller, собственной БД у модуля нет. Неизвестная стоимость предыдущих попыток, общий бюджет серии, cooldown и постоянная дедупликация решаются caller. Новый явный запуск получает новый ID. Callback не является техническим доказательством постоянной записи — её обеспечивает реализация caller.

Общий таймаут охватывает metadata, beforeSend, POST и чтение ответа. При истечении callback POST не произойдёт, даже если callback завершится позднее. Отмена/таймаут после отправки допускают состоявшуюся генерацию и списание. Retry-After возвращается как retryAt (секунды/HTTP date; при 429/503 с невалидным заголовком — 60 секунд); notBefore отклоняет преждевременный новый запуск без ожидания. Автоматического повторного POST, исправления JSON, дозагрузки фактов и смены модели нет.

## Итог попытки и ошибки

Identity содержит назначенные кодом matchId/side, bundleId/contextDigest, packageId/packageDigest/calibration, responseFormat/requestDigest. В AnalysisAttempt она находится в поле identity, а в StartedAttempt — плоско. При ошибке до проверки входа identity/attemptId могут быть null; непроверенные строки входа не отражаются в диагностике.

Статусы: preflight-failed, valid, invalid-output, api-error, transport-error, timed-out, aborted. `valid` означает структурную проверку, а не ручное подтверждение качества. Техническая ошибка имеет analysis null. Error содержит только закрытый code, допустимый httpStatus и известный apiType, без сырого сообщения провайдера. Офлайн-функции выбрасывают AnalysisError; сетевой вызов возвращает ожидаемые ошибки в результате.

Результат содержит UTC/elapsedMs, requestSent, доступные generationId/model/provider/finishReason, оценку/rates и usage. Метрики токенов и costUsd независимо равны null, когда неизвестны; известный ноль сохраняется. BillingState — not-sent, known или unknown. Известный usage сохраняется и для ошибочного/невалидного платного ответа; эвристическая цена не подставляется вместо фактической. Отдельного GET по generation ID нет.

Content и responseDigest доступны для локального ревью. При отражении ключа в content или экспортируемых строковых метаданных они не возвращаются; ошибка secret-in-output не содержит ключа. Headers, reasoning, произвольные provider metadata и сырые API errors не экспортируются. Запросы и реальные результаты сохраняет caller вне Git; модуль файлы не пишет.

Проверки и оставшиеся живые ограничения: [VERIFICATION.md](VERIFICATION.md).

## Новый аналитик Gemini

Отдельные функции `loadGeminiPromptPackage` / `createGeminiPromptPackage`, `prepareGeminiAnalysis`, `analyzeGeminiMatch`, `validateGeminiAnalysis`, `presentGeminiAnalysis` принимают новый CompactFactsBundle и пакет `analysis/prompts/gemini-v1`. Legacy API, форматы, запросы и значения по умолчанию сохранены. Новый формат принимается общим runtime по сохранённому профилю gemini; legacy DTO не меняются.

Профиль `gemini-match-v1`: google/gemini-3.8-flash, только google-ai-studio без fallback, temperature 0.65, low reasoning/exclude, max_tokens 2048, SSE с usage, timeout 180000 ms, maxRequestBytes 32768. Параметры/тарифы/лимиты endpoint проверяются свежим GET перед единственным POST. BeforeSend, явный предел оценочной стоимости, дедупликация попыток и сохранение результата — те же обязанности caller; новый тип started содержит responseFormat gemini-match-analysis-v1. Низкоуровневый analyzeGeminiMatch делает максимум один POST, без исправляющего запроса или отдельного roast. Ограниченный повтор лабораторного workflow описан ниже.

Ответ `gemini-match-analysis-v1`: version=1, selectedPlayerSlot, nomination (до 100 code points), facts (3–4 Claim до 240 символов с 1–6 уникальными evidenceIds), quoteId|null, verdict (до 400), confidence и до двух limitations по 160. Дополнительные поля запрещены. Игровые ссылки не принимают chat или полностью unavailable/пустую группу. Quote ID должен быть передан текущему запросу и принадлежать выбранному игроку. `presentGeminiAnalysis` возвращает ник/героя и точные текст/время/признак сокращения цитаты из проверенного контекста. Экранирование конечного интерфейса остаётся обязанностью renderer.

Структурная валидация не доказывает причинность, правильность выбора, качество шутки или полную независимость скрытого выбора от чата. Инструкция закрепляет выбор по игре и чат только для roast. Правило защиты саппортов требует одновременно нулевого вижена, нулевого урона, подтверждённого AFK-леса и KP<25%; AFK-лес во входе недоступен, поэтому его нельзя объявлять выполненным по GPM или обвинению. Это ограничение принятой эвристики, а не скрытое измерение AFK.

GeminiAttempt дополнительно содержит firstContentMs и streamBytes. SSE принимается только с корректным завершением [DONE] и finish_reason=stop. Финальный usage-кадр OpenRouter может повторять прежний finish_reason без нового текста; это учётный кадр. Новый текст после завершения, конфликт finish и отсутствие DONE отклоняются. Обрыв сохраняет полученные ID/usage/частичный непригодный content. HTTP 400 сохраняет безопасный статус/класс, доступный ID из ответа/заголовка и usage. Неизвестная стоимость — null/unknown, известный ноль остаётся нулём; оценка не заменяет списание. Токен и reasoning не экспортируются. Быстродействие и качество ещё не откалиброваны.

### Лабораторный запуск

По умолчанию `gemini-prepare` теперь выбирает отдельный `analysis/prompts/gemini-v2` / `gemini-match-v2`. Параметры и compact-вход прежние; ответ `version=2, format=gemini-match-analysis-v2` добавляет обязательные `teamFacts`: ровно три различных Claim с теми же пределами текста/игровых ссылок. Полные дубликаты отклоняются схемой, различие по смыслу проверяется при ревью. Verdict допускает до 700 code points: инструкция просит 2–3 едких предложения с игровым панчлайном и собственной цитатой. Мат и игровые гиперболы разрешены; числа и цитаты берутся из контекста.

`teamFacts` рассматривают всю команду: шуточные объяснения поражения, после победы — слабые места. Чат в игровых основаниях запрещён. Пользователь одобрил подачу первого реального v2: гиперболы и вольные игровые выводы допустимы и не блокируют приёмку текста. Постоянная доказательность причинности и оговорки не требуются; limitations может быть пустым. Числовая основа и авторство цитат сохраняются. Техническая схема остаётся строгой: инструкция явно задаёт `"version": 2`, `"format": "gemini-match-analysis-v2"` и запрещает копировать входную метку; транспорт отклоняет неверную версию/формат без автоматического исправления.

`renderGeminiAnalysis(analysis, bundle)` формирует локальное Markdown-превью с экранированием текста, атрибуцией цитаты и отметкой сокращения. После roast, оговорок и ссылки в самом конце идут ровно три пункта под заголовком «Почему проебали» или «Где накосячили, несмотря на победу». Лаборатория сохраняет v2 в `presentation.json` и `presentation.md`. Это тот же единственный запрос; дополнительной генерации финального блока нет. Исторические Gemini v1-планы загружают свой пакет и сохраняют прежние request/digest/формат без командного блока. Discord/VPS пока используют прежний runtime.

```powershell
npm.cmd run build
npm.cmd run lab -- gemini-prepare --match-id 9048915444 --side dire
npm.cmd run lab -- gemini-run --plan '<каталог из gemini-prepare>' --budget-usd 0.25
```

`gemini-prepare` читает только локальный corpus, проверяет снимок, сохраняет compact facts и неизменяемые request/package/plan. Ключ не нужен. `gemini-run` явно выполняет платную попытку с OPENROUTER_API_KEY из окружения; подготовка её сама не запускает. При отдельном management key возможен один ограниченный повтор по правилам ниже. Бюджет учитывает все предыдущие Gemini-попытки root: known расход, точные management-сверки и положительные резервы на unknown/незавершённые started. Для старых неизвестных расходов без новой сверки по-прежнему нужен `--reserve-unknown-usd`; резерв не является списанием. Retry-After сохраняется. Лабораторные legacy run/report и их журналы не меняют формат и не объединяются с новым отчётом.

Артефакты отдельно в root/gemini-plans и root/gemini-runs; started записывается атомарно до POST, затем attempt и при valid — presentation. Active.lock запрещает параллельные Gemini-запуски одного root; после аварийного завершения lock остаётся для ручной проверки журнала, не удаляется автоматически. Нет Discord-публикации, калибровки или смены VPS. Следующий этап подключения: новый контракт storage, явный профиль pipeline/operations и новый Discord renderer с проверяемой собственной цитатой; правила выбора стороны по Steam32 сохраняются.

### Management-сверка и один повтор

CLI читает необязательный `OPENROUTER_MANAGEMENT_KEY` из окружения процесса; `.env` автоматически не загружается. Он передаётся только management endpoint, обычный `OPENROUTER_API_KEY` — только inference. Совпадающие ключи отклоняются до отправки. В production runtime эта логика пока не подключена.

`analyzeGeminiMatch` по-прежнему делает максимум один POST и теперь добавляет `x-session-id=attemptId`, не меняя тело/digest. [OpenRouter](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request?explorer=true) поддерживает этот заголовок для группировки запросов. Метка служит корреляции и не является ключом идемпотентности.

`checkGeminiRecovery` применим к transport-error/timeout до получения HTTP-ответа, когда нет generation ID, текста, stream bytes и usage. Он делает management Analytics-запросы по точной session_id после последовательных пауз 10, 20 и 30 секунд — примерно на 10/30/60-й секунде после сбоя плюс сетевое время проверок.

| Сверка | Поведение |
|---|---|
| Найдена запись, в том числе с задержкой | Повтора нет. ID сохраняется; GET generation уточняет точную стоимость. Ошибка получения стоимости не разрешает генерацию. |
| Три полных свежих пустых результата | Один новый POST с новой меткой, после сохранения решения и бюджетного резерва. |
| Нет ключа, ошибка/предупреждение API, stale/truncated/malformed ответ, отмена | Повтора нет. |
| Уже были HTTP-ответ, ID, content/usage, невалидный JSON | Автоматического повтора нет. |
| Вторая попытка тоже упала | Третьего POST нет. |

Под одним active.lock первая попытка сохраняется без изменений; решение — в её `recovery.json`, разрешение повтора — в `retry-intent.json`. Новая попытка получает отдельный каталог и `retryOf` в run.json. CLI показывает общий фактический счётчик POST, итоговый статус и сверку. Найденный ID/стоимость не подменяют analysis исходной ошибки; восстановления текста в этом workflow нет.

Перед повтором остаётся положительный резерв в размере консервативной оценки первого запроса. На второй запрос заново проверяются endpoint, тарифы, оставшийся бюджет и started. Будущие запуски читают связанную management-стоимость/резерв из sidecar, не переписывая исходный usage. Нельзя объявить расход нулевым только по отсутствию записи. Analytics может запаздывать: три пустых проверки не гарантируют отсутствие дубликата, поэтому максимум один повтор и резерв сохраняются.

## Подключение runtime Gemini

Общий runtime теперь использует отдельные типы AnalysisProfile, RuntimeBundle/Prepared/Started/Attempt и проверки isGeminiBundle/isGeminiPrepared/isGeminiAttempt. Прежние AnalysisAttempt, PreparedAnalysis и функции не меняют формат. Gemini v1/v2 сохраняются как исходные Gemini DTO; преобразования в match-analysis-v1 нет. Наличие интеграции не означает калибровку качества, низкую latency провайдера или доставку на VPS.

checkGeminiRecovery принимает необязательный now() вместе с wait(ms, signal): production использует Date.now, pipeline передаёт свои Clock и отменяемое ожидание. Отдельный management key используется только при live и eligible полном final, а не при одном started. Дальнейшее решение и единственный дочерний attempt фиксирует storage. См. [pipeline](../match-pipeline/README.md).
