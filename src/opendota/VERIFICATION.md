# Проверка клиента OpenDota — 17 октября 2026

Реализованы пять публичных операций в `src/opendota/`, без дополнительных зависимостей и изменений соседних модулей. Существующая TypeScript-сборка переиспользована. [Инструкция](README.md), [OpenSpec](../../openspec/changes/add-opendota-client/specs/opendota-client/spec.md).

## Изолированные проверки

- Windows, Node.js 22.14.0; TypeScript, встроенные fetch/AbortController и node:test.
- Сборка и `npm.cmd run typecheck` проходят. `openspec.cmd validate add-opendota-client --type change --strict --no-interactive` проходит.
- Весь набор: 153/153 теста, включая 31 новый тест клиента и 122 существовавших. Сеть и часы клиента подменены; реальные parse jobs в тестах не создаются.
- Проверены ID/страницы/таймауты, отказ до сети, история без фильтров, победа/поражение, обе стороны и неполный состав, анонимность, отсутствие/null/0/пустые массивы и дополнительные поля.
- Две фикстуры получены обезличенной проекцией локальных снимков 9044556864 и 9046778399; источник и SHA-256 сохранены в test/opendota-fixtures.ts. Account ID, ник, чат и прочие персональные поля исключены. Basic в тестах является производной фикстурой, а не сохранённым прежним ответом API.
- Проверены постоянные HTTP ошибки, 429, неверный JSON, обрыв fetch/тела, зависший HTTP/JSON, два повтора GET с задержками/jitter, единственный POST и requestMayHaveSucceeded.
- Проверены скользящий бюджет и веса, расход повторов, совместное действие локального бюджета/cooldown, Retry-After (секунды/HTTP-date/fallback), отсутствие скрытой очереди.
- Проверены TTL и предел 100 записей, вытеснение, копии, retrievedAt, fresh, отсутствие кеширования ошибок/job, объединение GET без signal, независимость сигналов и защита от восстановления старого кеша завершившимся после POST чтением.
- Проверены объединённый POST, отмена одного/всех подписчиков до отправки, отмена после отправки, сохранение общего HTTP для других подписчиков, очистка таймеров и дальнейший отдельный явный POST.
- Проверены basic → missing → parsed, известный job ID после восстановления, соответствие job/match, общий срок HTTP/повторов/задержек, временные ошибки/retryAt, последний снимок/ошибка, отмена polling и граница срока до обработки таймера.
- Пример README совпадает с компилируемым test/opendota-example.ts и выполняется на подменённом API для готового и базового матча. `.env.example` содержит только пустые значения; ключ передаётся вызывающим кодом. Проверены Bearer без query, отсутствие ключа/cause/сырого тела в диагностике и отказ при отражении ключа в успешном ответе.

Полный набор запускался с локальными разрешениями Windows для существующих файловых тестов лаборатории, которым необходим hard link. Финальный протокол: `.local/opendota/tests-final-c3b33bd3-415c-41bd-9ea2-6665497c031f.tap`. Рабочие файлы и протоколы находятся только в `.local/`.

## Ограничения

Реальный POST/опрос живой очереди самим клиентом не выполнялся: оба матча уже разобраны. Этот путь проверен изолированными сценариями; предыдущая прямая проверка API описана в design.md. Живые 429, длительная очередь, недоступный реплей и авторизация с реальным OpenDota-ключом не воспроизводились. Linux runtime пока не запускался; используются стандартные переносимые API Node.js.

Подключение клиента к лабораторному collect, будущему pipeline/хранилищу и Discord не входит в эту реализацию. Постоянная дедупликация и сохранение job ID остаются у вызывающего модуля. Изменение не архивировалось.
