# Проверки storage

Проверено 17 октября 2026 на Windows x64, Node.js v22.14.0, встроенная SQLite 3.47.2. Это минимальная версия Node проекта. Зависимости и код соседних модулей в этом изменении не менялись.

| Проверка | Результат |
|---|---|
| `npm.cmd run typecheck` | успешно |
| `node --test dist/test/storage*.test.js` после build | 47/47 |
| `npm.cmd test` с разрешением файловых ссылок | 212/212, включая прежние 165 тестов |
| `openspec.cmd validate add-storage --type change --strict --no-interactive` | успешно |

Первый общий прогон в песочнице дал 155/212: в существующей лаборатории зафиксирован EPERM на fs.link во временном каталоге. Повтор того же npm test с разрешениями на файловые операции дал 212/212. Код лаборатории для обхода ограничения не менялся. Проверки storage проходили и в песочнице.

## Ограничения

- Linux runtime не запускался; успешной Linux-проверки пока нет.
- На Node.js 22.14 node:sqlite экспериментален и выдаёт ExperimentalWarning. Файловая работа и используемый API проверены именно на указанной версии; иные версии Node требуют проверки.
- SIGKILL проверяет сбой процесса, а не отключение питания, неисправность диска или сетевую файловую систему.
- Общий bootstrap, pipeline, обработка Discord-команд, публикация и бюджетная политика ещё не подключены; контракт существующего аналитика проверен локально.
- В папке нет Git-репозитория, поэтому git diff/check-ignore недоступны. Новые исходники/документы находятся в src/storage и test/storage*, служебные файлы — только во временных каталогах. Существующий .gitignore содержит .local/ для будущей рабочей БД и её журнала.
