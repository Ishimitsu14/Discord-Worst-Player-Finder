# Работа с проектом

- Общий план и согласованные решения находятся в [PROJECT_PLAN.md](PROJECT_PLAN.md). Перед работой прочитай его; затем загружай документы выбранного модуля и только необходимые контракты соседних модулей.
- Не требуй историю предыдущих чатов, если ответ есть в файлах проекта. План — обзор; подробные требования и технические решения находятся в OpenSpec.
- Используй установленные OpenSpec skills для подготовки, обновления и реализации изменений. Просьба сделать спеку означает работу с документами; реализацию начинай по отдельному запросу пользователя.
- Сначала анализируй существующий код и соглашения. Сохраняй структуру, именование, форматирование и паттерны проекта. Используй существующие компоненты и библиотеки, если они подходят.
- Комментируй только сложную и неочевидную логику. Нестандартное, рискованное или существенно отличающееся от текущих подходов решение сначала опиши и согласуй с пользователем.
- Если прислан дизайн Figma, изучи его перед работой над интерфейсом. Для браузерных проверок на Windows используй Playwright MCP.
- Работай в пределах выбранного модуля. Перед изменением общего файла перечитай его: другие чаты могут работать с этой же папкой. Не перезаписывай чужие решения и изменения.
- После подготовки или реализации модуля обновляй только его статус и ссылку в PROJECT_PLAN.md; общие решения меняй при согласованных изменениях требований.
- Готовая спека не означает готовую реализацию. Статус задач сверяй через OpenSpec и фактические файлы; задачи отмечай выполненными только после реализации и проверки.
- Секреты, токены, локальные настройки Codex и состояние браузера держи вне Git. Не запрашивай значения ключей в чате.
